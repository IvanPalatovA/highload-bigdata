# Журнал работ (Вариант 93)

## ЛР1. Стенд и сбор данных

### Принятые решения по сборщику
1. **Источник и фильтрация**: Источник GH Archive отдаёт почасовые сжатые файлы `.json.gz`. Сборщик скачивает поток через `requests.get(..., stream=True)`, распаковывает его на лету через `zlib.decompressobj` без загрузки всего архива в ОЗУ (укладываясь в лимит 512 МБ) и оставляет только события из `SOURCE_FILTER=CreateEvent,DeleteEvent,ReleaseEvent`.
2. **Ключ и время события**: В качестве `event_key` выбран уникальный идентификатор события GitHub `id`. Время `event_time` берётся из поля `created_at` и нормализуется к ISO 8601 UTC с миллисекундами (`.000Z`).
3. **Атомарность и сохранение позиции**: Каждый часовой файл сначала записывается во временный файл `.tmp-*.jsonl.gz`, после чего атомарно переименовывается через `os.replace`. Список обработанных часов и последних ключей сохраняется в `/data/raw/state/`, что исключает появление дублей при перезапуске службы.
4. **Ротация и метрики**: После закрытия каждого файла проверяется суммарный объём `stream` и `history`; при превышении `COLLECTOR_RAW_LIMIT_GB=20` удаляются самые старые файлы. На порту `9101/metrics` поднят HTTP-сервер в формате Prometheus.

### Замеры объёмов
- Доля фильтра: из ~2160 событий/мин полного потока фильтр `CreateEvent,DeleteEvent,ReleaseEvent` оставляет ~180 событий/мин (~8,3% потока).
- Суточный объём после фильтра: ~200 МБ до сжатия, ~34 МБ после сжатия gzip (коэффициент сжатия ~5,8x).
- Оценка на 8 недель потока + 7 дней истории: 63 * 0,034 = 2,14 ГБ, что с запасом укладывается в лимит 20 ГБ.
