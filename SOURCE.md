# Паспорт источника: GH Archive (публичные события GitHub)

## Доступ
- адрес потока и способ получения: `https://data.gharchive.org/<ГГГГ-ММ-ДД>-<час>.json.gz` (час от 0 до 23 без ведущего нуля); загрузка нового часового архива по расписанию после окончания часа.
- адрес исторического среза и способ загрузки: те же почасовые архивы `https://data.gharchive.org/<ГГГГ-ММ-ДД>-<час>.json.gz` за период `COLLECTOR_HISTORY_FROM` .. `COLLECTOR_HISTORY_TO`.
- глубина доступной истории: сплошной архив с 12 февраля 2011 года по текущий момент.
- схема истории: те же события и тот же ключ (`id`); пропуски в записи потока закрываются загрузкой недостающих часовых архивов теми же событиями.

## Лицензия и условия использования
- код проекта GH Archive — MIT License, материалы сайта — CC BY 4.0;
- события — публичные данные GitHub, распространяются на условиях GitHub Terms of Service;
- собранные данные используются исключительно в учебных целях на локальном стенде и не публикуются.

## Лимиты и представление клиента
- жёсткие лимиты API не объявлены; файлы загружаются последовательно по одному, проверка нового файла раз в `COLLECTOR_POLL_SECONDS=60` секунд;
- при ответах `429` и `5xx` либо сетевых сбоях применяется повтор с экспоненциально растущей паузой (backoff от 2 до 60 с);
- заголовок клиента: `User-Agent: mephi-bigdata-collector-v93/1.0 (palatov.vanya@gmail.com)`.

## Схема события
| Поле | Тип | Смысл | Пример |
|---|---|---|---|
| `event_key` | string | Идемпотентный ключ события (равен `id`) | `"39485729104"` |
| `event_time` | string (ISO 8601 UTC) | Время создания события в UTC с миллисекундами | `"2026-10-14T12:34:56.000Z"` |
| `received_at` | string (ISO 8601 UTC) | Время получения события сборщиком в UTC | `"2026-10-14T14:05:10.123Z"` |
| `source` | string | Код источника данных по варианту | `"github"` |
| `id` | string | Уникальный идентификатор события GitHub | `"39485729104"` |
| `type` | string | Тип события GitHub (поле фильтрации) | `"CreateEvent"` |
| `public` | boolean | Признак публичного события | `true` |
| `actor_id` | integer | Числовой ID пользователя GitHub | `583231` |
| `actor_login` | string | Логин пользователя GitHub | `"octocat"` |
| `repo_id` | integer | Числовой ID репозитория | `1296269` |
| `repo_name` | string | Полное имя репозитория (`owner/repo`) | `"octocat/Hello-World"` |
| `org_id` | integer / null | Числовой ID организации (если есть) | `1342004` |
| `org_login` | string / null | Логин организации (если есть) | `"github"` |
| `ref_type` | string / null | Тип объекта в Create/Delete (`branch`, `tag`, `repository`) | `"branch"` |
| `ref` | string / null | Имя ветки или тега | `"main"` |
| `master_branch` | string / null | Ветка по умолчанию репозитория | `"main"` |
| `description` | string / null | Описание репозитория | `"Test repo"` |
| `pusher_type` | string / null | Тип инициатора (`user` или `deploy_key`) | `"user"` |

- ключ события: `id` (строковый идентификатор события GitHub, глобально уникален в рамках всех событий GitHub).
- время события: `created_at` (приводится к `event_time` в формате ISO 8601 UTC с точностью до миллисекунд).

## Фильтр потока и объёмы
- фильтр задания: `CreateEvent,DeleteEvent,ReleaseEvent`
- интервал наблюдения: `2026-10-08 — 2026-10-16`

| Показатель | До фильтра | После фильтра |
|---|---|---|
| событий в минуту | ~2 160 | ~180 |
| байт в сутки до сжатия | ~2 400 000 000 (2,4 ГБ) | ~200 000 000 (200 МБ) |
| байт в сутки после сжатия | ~410 000 000 (0,41 ГБ) | ~34 000 000 (0,034 ГБ) |

- восемь недель после фильтра и сжатия: **1,9 ГБ** (вместе с 7 сутками исторического среза ~ **2,14 ГБ**) при пределе `COLLECTOR_RAW_LIMIT_GB = 20` ГБ.
- ограничение, которое наступит первым при росте потока: **диск (предел 20 ГБ слоя сырых данных)** и **пропускная способность сети / время последовательного скачивания часового архива** (память 512 МБ не переполняется благодаря потоковой распаковке `zlib.decompressobj`).

## Известные дефекты
- Часовые архивы GH Archive публикуются с задержкой (15–45 минут после окончания часа). Сборщик запрашивает архивы с отступом и при коде 404 повторяет попытку позже.
- Часть часовых файлов в истории источника может быть неполной (размер в разы меньше соседних).
- При перезапуске сборщика или повторном чтении часа возможны дубликаты событий — отбрасываются сборщиком по множеству `seen_keys` (`event_key`).
